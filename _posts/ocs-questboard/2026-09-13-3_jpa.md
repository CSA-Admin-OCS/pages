# Phase 2: Database Schema & Persistence

## What I Built

For Phase 2, I converted my `Questboard` POJO into a JPA entity so that my quest data could be stored in a SQLite database.

I added the `@Entity` annotation to tell Spring Data JPA and Hibernate that the `Questboard` class should be mapped to a database table. I also used `@Id` and `@GeneratedValue` on the `id` field so that each quest has a unique primary key that can be automatically generated by the database.

## How I Built It

```java
package com.open.spring.mvc.questboard;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;

@Entity
@Data
@NoArgsConstructor
@AllArgsConstructor
public class Questboard {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String title;
    private String description;
    private String difficulty;
    private int xp;
    private String status;
    private String deadline;
}
```

## Relational Schema

The `Questboard` class is mapped to a database table. Each object field becomes a column in the table.

| Field         | Java Type | Database Purpose                                |
| ------------- | --------- | ----------------------------------------------- |
| `id`          | `Long`    | Primary key that uniquely identifies each quest |
| `title`       | `String`  | Stores the name of the quest                    |
| `description` | `String`  | Stores details about the quest                  |
| `difficulty`  | `String`  | Stores the difficulty level                     |
| `xp`          | `int`     | Stores the experience-point reward              |
| `status`      | `String`  | Stores the current quest status                 |
| `deadline`    | `String`  | Stores the quest deadline                       |

The `id` field is the primary key because every quest needs a unique identifier. I used `Long` because the database generates the ID, meaning a new Questboard object can initially have a null ID before it is saved.

## JPA Mapping

The `@Entity` annotation tells JPA to treat `Questboard` as a persistent entity. The `@Id` annotation identifies the primary key, while `@GeneratedValue(strategy = GenerationType.IDENTITY)` allows the database to automatically generate the ID.

The remaining instance variables are mapped to columns in the Questboard table. This allows Java objects to be converted into database records without manually writing SQL for every operation.

## Database Design Decisions

I chose separate fields for the title, description, difficulty, XP, status, and deadline because each represents a different piece of information about a quest.

I used an integer for XP because experience points are numerical values that can be used in calculations. I used Strings for difficulty and status because the values currently represent labels such as `HARD` and `OPEN`.

I used a `Long` primary key so that each quest can be uniquely identified and referenced by other parts of the application.

Currently, the Questboard entity does not have any relationships or foreign keys to other entities. Each quest can therefore exist independently in the database.

## Schema Validation

After starting the Spring Boot application, Hibernate created the Questboard table in my SQLite database. I opened the SQLite database in VS Code and verified that the table and its columns were created.
